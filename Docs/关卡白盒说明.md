# 龙眠王庭：关卡白盒说明

## 本版要验证的设计问题

1. 玩家能否在安全位置辨认下一处遮挡，理解何时应该移动？
2. 同一威胁能否让低位与高位路线产生不同体验？
3. 玩家能否把外庭学到的遮挡规则应用到更开放的中央庭院？
4. 从地面潜入到登龙俯瞰，是否能改变玩家对建筑尺度的理解？

这是第一轮可导入 Unity 的白盒实现。视觉精修、声效、实测节奏与正式玩法验收均留待引擎内完成。

## 地图坐标和尺寸

Unity 世界坐标中：X 为东西，Z 增大朝北，Y 为高度；1 单位 = 1 米。

主路线从 `(0,0,4)` 出发，终点为 `(0,0,166)`。可玩区域主轴长约 178 米，外庭和中央庭院宽约 76 米；远景塔楼不属于通行路线。

| 区域 | 坐标范围 / 高度 | 白盒组织 | 设计作用 |
|---|---|---|---|
| A 山道 | Z 0–22；Y 0 | 12m 宽狭长入口、末端岩棚替身 | 建立人体尺度、先认识天空中的威胁 |
| B 外庭 | Z 22–52；Y 0 | 76m 宽；两处中轴顶棚；两侧残墙 | 观察、短穿越、选择东西支线 |
| C1 礼拜堂 | X -37…-23，Z 52–100；Y 0 | 两段顶棚，中部约 5m 破口，北端栅门 | 较多遮蔽；壁画探索；中途不能把室内等同绝对安全 |
| C2 钟楼连廊 | X 23…37，Z 42–102；Y 0→8→0 | 20m 上坡、高位通道、中部钟室、10m 下坡 | 换取观察高度与诱导交互，承担更多暴露风险 |
| D 中央王庭 | X ±38，Z 100–136；Y 0/-3 | 双侧断续拱廊、两处石像残块、中央下沉花园 | 组合教学、局部路线选择、改变观察角度 |
| E 断顶回廊 | X ±6，Z 136–156；Y 0 | 入口顶棚、中继顶棚、两段断口 | 在已知规则下连续判断与穿越 |
| F 圣剑殿 | X ±20，Z 156–178；Y 0 | 大柱、金色圣剑、终点安全区 | 拔剑、登龙、飞越旧地图 |

中央坍塌建筑占 X ±22、Z 52–100，阻止从外庭直穿终点，并分隔两条支线。当前是实体体块，没有可探索内室。

## 动线与玩家决策

```text
起点 → 外庭 ┬→ 礼拜堂（低位、顶棚多、壁画与栅门）─┐
             └→ 钟楼（高位、较暴露、钟声诱导）─────┤
                                                   ↓
                                   中央庭院：左右拱廊 / 下沉花园
                                                   ↓
                                     断顶回廊 → 圣剑殿 → 骑龙
```

两条支线都能独立抵达终点，没有必须跑遍所有支线的收集条件。当前栅门是礼拜堂路线中的交互门，**尚不是连接两地的新捷径**。开启后重试保留，避免重复操作。

下沉花园的地面实际位于 Y=-3。南坡 Z104–112 下降，北坡 Z122–130 上升。上层地板已分割，避免出现下沉空间被完整地板封住的问题。

## 巨龙规则和白盒表现

- 巡游使用空中目标椭圆：横向半径约 46m，纵向半径约 48m，中心 Z94；目标周期 56 秒，实际运动受追赶速度影响。
- 观察点位于龙头，感知方向为身体前方偏下。范围 82m，锥体半角约 65°。
- 每 0.1 秒检测角色躯干和头部附近两个采样点；任一点无遮挡即可被看见。
- 站立持续可见时发现值约 2.5 秒充满，蹲伏约 4.2 秒；失去视线时逐渐下降。
- 警觉后搜索最后发现位置。未继续看见玩家时，不更新到玩家的隐藏位置。
- 发现值满后锁定最后发现点，出现半径 7m 的橙色预警区，2.8 秒后结算龙息。离开区域或获得实体遮挡可脱险。
- 圣剑殿（Z≥157）停止新增发现。检查点本身不提供永久隐身，屋檐边缘仍需留意斜向视线。

龙息目前用预警圆盘与命中判定表达，无伤害动画与成品喷火特效。巨龙采用约 42m 翼展的体块替身，有简单振翅；没有复杂骨骼动画或动态导航。

## 失败、探索与结尾

检查点依次为山道起点、外庭入口、支线出口、最终回廊入口。龙息命中、跌落或按 R 返回最近检查点，重置巨龙警觉，保留已打开的门和已读壁画。

拔剑触发约 6 秒巨龙靠近，再进入约 48 秒固定航线。角色显示在龙背上；镜头经过中央庭院、双支线、外庭与山道，再升空。Q/E 可左右偏转观察。当前没有自由飞行和手动攀爬登龙。

## 可修改入口

- `Assets/DragonCourt/Resources/WhiteboxLayout.json`：地板、顶棚、墙体、坡道数据。
- `CourtBuilder.cs`：角色、巨龙、交互目标、光照、标识的生成。
- `CourtDragon.cs`：巡游、视野、发现速度、搜索、攻击。
- `CourtFlow.cs`：检查点、栅门、壁画、诱导、胜利、骑龙路径。
- `CourtPlayer.cs`：角色速度、蹲伏、碰撞、相机。

修改 JSON 后重新生成可编辑场景才会更新；单独修改生成场景，不会反向写回 JSON。应选择一种方式作为该轮迭代的数据来源。

## 第一轮试玩记录建议

记录首次看到终点的位置、两条支线选择率与理由、每次发现时的具体坐标、中央庭院的停顿位置、断顶回廊失败次数，以及结尾是否能认出此前走过的路。

优先调整下一处遮挡的可见性、顶棚缺口与巡游方向，再调整速度。若玩家只是站在屋檐下长时间等机会，应缩短危险区或增加可被理解的替代路线。

目前尚无真人试玩数据。求职展示中应将本版标为白盒原型，并展示自己的实测记录和后续调整，不把初始参数当作验证结果。
